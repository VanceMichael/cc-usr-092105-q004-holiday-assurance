# 领域约定

## 核心对象

- 商户能力：商户按产品与出行日期申报的可售名额，只追加不篡改
- 团购产品：住宿、餐饮或旅行产品及其团购券规则版本
- 保障规则：按版本发布，订单冻结下单时有效版本的快照
- 履约事件：核销记录与线路停发等履约过程事实
- 补偿记录：按冻结版本的赔付标准发放，同一订单同一原因只发一次
- 订单快照：订单及其冻结的保障版本与券规则
- 外呼任务：高风险订单在履约前的人工确认动作
- 巡检结论：按商户与品类判定风险等级
- 联系偏好：消费者可接受的外呼渠道与时段

## 已知规则

- 订单采用下单时有效的保障版本
- 容量扣减必须具备幂等键
- 巡检风险不能对无关商户扩大披露
- 取消范围与赔付标准按下单时冻结的保障版本执行
- 商户改量、线路停发与部分核销不得覆盖已确认订单
- 高风险订单在履约前进入外呼或人工确认
- 补偿对同一订单同一原因只发放一次

## 中台模块

`src/assurance.js` 实现上述规则：接收 `contracts/intake.schema.json` 定义的六类资料与管控事件，所有回调按幂等键去重；余量检查与扣减同步完成，同一名额不会被并发占用；`trace(order_id)` 为客服还原商户当时申报的能力、平台采取的预防动作以及最终退款或履约结果。跨进程部署时，存储层须对 `(product_id, use_date)` 的余量扣减与 `(order_id, reason)` 的补偿键提供唯一约束。

样例中的名称和编号仅用于说明字段关系，不能对应到现实中的个人、企业或业务记录。
