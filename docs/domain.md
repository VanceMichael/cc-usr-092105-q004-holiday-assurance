# 领域约定

## 核心对象

- **商户能力**：商户按产品+日期申报的可售量（房量/名额/位量），只追加申报记录，首报与每次改量都留痕
- **团购产品**：券面权益（份数、品类、是否高风险品类），登记后不可覆盖
- **保障规则版本**：取消档位 + 赔付标准，只增不改；订单持有下单时刻的冻结快照
- **订单与冻结快照**：下单时把保障版本、联系偏好、权益明细一并冻结进订单
- **容量占用**：按幂等键落账的名额占用，状态机 held → confirmed → released
- **履约事件**：只追加的事件流（申报、占用、改量、停发、核销、预防动作、退款、赔付）
- **核销记录**：支持部分核销的明细记录，按幂等键去重
- **巡检结论**：按商户归集，复查通过可消除历史结论
- **预防动作**：外呼或人工确认任务，履约前必须闭环
- **退款/补偿记录**：退款一笔订单一次；补偿同一订单同一理由一次
- **投诉溯源视图**：一次投诉直接看到申报能力、预防动作与最终结果

## 已知规则

1. 订单采用下单时有效的保障版本，取消范围与赔付标准按该版本冻结；商户改规则只发布新版本
2. 容量扣减、核销、取消、补偿等所有写操作必须具备幂等键；重复回调（含并发同键）只执行一次
3. 同一名额不能被并发或重复占用，超额占用直接拒绝（SOLD_OUT）
4. 商户改量只追加申报记录；下调击穿承诺线时，按"最晚占用先受影响"的确定性规则显式挑出订单
5. 线路停发只拒绝新单，已承诺订单进入预防名单，不能被悄悄取消
6. 部分核销只追加核销明细，原订单权益与未核销部分的赔付标准保持不变；超量核销被拒
7. 补偿对同一订单同一理由只发一次；同一理由按不同标准重发会被显式拒绝
8. 巡检风险只对涉事商户可见，不向无关商户扩大披露
9. 高风险订单未完成预防动作时，履约闸口一律拦截；中风险只提示不阻断
10. 联系偏好决定触达渠道：电话偏好走外呼，其余走人工确认，绝不静默跳过

## 模块对照

| 模块 | 职责 |
| --- | --- |
| `src/assurance-versions.js` | 保障版本目录：只增不改，下单冻结快照 |
| `src/capacity.js` | 容量台账：幂等占用、改量留痕、停发保承诺 |
| `src/idempotency.js` | 回调幂等网关：重复回放、并发同键共享执行、异载荷判冲突 |
| `src/promises.js` | 承诺台账：原承诺 + 只追加修订 |
| `src/orders.js` | 订单状态机：高风险挂起才能进履约 |
| `src/verification.js` | 核销台账：部分核销、超量拒绝、幂等去重 |
| `src/compensation.js` | 补偿台账：同一订单同一理由只发一次 |
| `src/inspections.js` | 巡检结论：按商户隔离，复查可消除 |
| `src/outreach.js` | 外呼/人工确认看板：一单一任务，升级不重复派发 |
| `src/settlement.js` | 退款：按冻结版本档位计算，一笔订单只退一次 |
| `src/risk.js` | 风险引擎：汇总申报/巡检/容量信号定级 |
| `src/complaint-trace.js` | 投诉溯源视图组装 |
| `src/platform.js` | 门面编排：下单、回调、取消、闸口、溯源 |
| `src/scenario-runner.js` | 场景样例回放器 |

样例中的名称和编号仅用于说明字段关系，不能对应到现实中的个人、企业或业务记录。
